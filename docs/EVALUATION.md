# 评估与验收方法

## 功能验收

使用固定的 50 条样本验证导入、分析、原文定位、人工修改与报告导出。样本应覆盖多问题评论、空泛评价、反讽、重复表述及信息不足的情况。

通过条件包括：原始评论可追溯；同一批次不会重复计数；人工修正可以保存；导出的数量与界面一致；模型失败不会被当作分析成功。

## 质量评估

先编写标注规则，再人工标注评估样本。用于调整提示词的样本与最终验收样本分开，避免把已反复调试的结果当作独立评估。

- 分类质量：统计分类正确、错误和难以判断的数量。
- 问题提取：记录遗漏问题、错误新增问题和摘要失真。
- 原文证据：验证引用片段是否存在且能支持摘要。
- 相似问题归组：记录错误合并与漏合并，展示代表性错误案例。

样本量和标注方法应与结果一起报告。仅由开发者标注的结果应标明为个人评估。

## 效率与成本

选择数量和复杂程度接近的两组反馈，分别计时人工整理，以及 AI 整理加人工复核。采用相同的最终交付要求，并记录样本差异和熟悉程度可能造成的影响。

记录以下数据：

- 评论条数和总字符数。
- 人工整理耗时。
- 模型处理耗时和人工复核耗时。
- 请求数量、重试数量及实际接口成本。
- 需要人工改动的条数，以及未能完成的条数。

不要预填节省比例、准确率或成本数字。完成实测后，再更新 README、演示材料与简历中的结果描述。
