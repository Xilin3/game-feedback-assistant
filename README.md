# 游戏玩家反馈整理助手

Game Feedback Assistant 面向游戏产品与运营人员，将玩家评论整理成有原文依据、可人工复核的问题清单，帮助团队处理重复反馈和准备分析报告。

## 项目内容

本仓库已建立产品方案、数据结构示例、开发清单与验收标准，作为首版开发的起点。核心功能的实现与验证进度记录在 [ROADMAP.md](ROADMAP.md)。

## 核心流程

导入评论 → AI 提取问题 → 相似反馈归组 → 查看证据与人工修正 → 导出报告。

例如，一条反馈“更新后进入地图就闪退，重装后仍然存在”，应提取为稳定性问题，保留触发场景、已尝试操作和对应原文，同时将设备配置、具体地图等缺失信息列为待核实项。

## 首版范围

- 一款游戏、一批固定评论，优先支持粘贴文本和 JSON 导入。
- 按 Bug、性能、操作体验、玩法建议等类别提取问题，一条评论可以包含多个问题。
- 合并同类反馈，保留每个问题关联的评论 ID 和原文证据。
- 允许人工修改分类、拆分或合并分组、标记信息不足。
- 导出 Markdown 报告，包含问题清单、样本内数量、代表性原文和待核实事项。

后续扩展：通过 Steam 评论接口获取公开反馈，以及上传反馈截图进行 OCR。截图输入在基础文本流程通过验收后接入。

## 实现方案

- Python 处理数据导入、模型请求、结果校验和报告导出。
- SQLite 保存原始评论、分析结果与人工修正记录。
- 简单 Web 界面展示分组、原文与人工修正操作。
- 大模型承担语义提取与相似问题归组；程序负责计数、来源追溯和格式校验。

当前尚未提供可启动的应用或安装命令；实现时应同步补充依赖文件、配置示例和运行说明。

## 数据来源

Steam 官方提供按应用获取用户评论的接口，支持游标分页，返回评论文本、时间和推荐状态等字段。接入说明见 [Steamworks 评论接口文档](https://partner.steamgames.com/doc/store/getreviews)。

仓库内的示例均为人工构造，用于说明输入结构，不代表任何真实游戏或玩家。真实样本的获取条件、语言、时间范围和数量应单独记录；分析报告中的占比仅描述所导入的样本。

## 演示与评估

首轮验收目标是完成 50 条反馈的端到端处理，再扩大到约 300 条真实评论。展示内容应包括导入、分析、原文定位、人工修正和报告导出，并记录耗时、人工复核结果和接口成本。

上述数量为开发与验收目标，不是已完成的处理规模或效果数据。
